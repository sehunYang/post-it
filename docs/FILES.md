# 사진·파일 공유 규약

웹앱 · Windows 위젯 · 안드로이드 앱이 모두 이 규약을 따릅니다. 하나를 바꾸면 세 곳과
`database.rules.json` · `storage.rules` 를 함께 바꿉니다.

## 저장 위치

- **파일 본체** — Cloud Storage for Firebase. 경로 `users/{uid}/{noteId}/{i}/{name}`
  - `{i}` 는 글 안에서의 순서(0부터). 같은 이름의 파일 두 개가 한 글에 들어와도 겹치지 않습니다.
  - `{name}` 은 아래 "파일 이름 다듬기" 를 거친 이름.
- **글(메타데이터)** — Realtime Database `users/{uid}/notes/{noteId}` 에 기존 글과 같은 자리.

```jsonc
{
  "text": "스크린샷.png, 보고서.pdf",   // 파일 이름들을 ", " 로 이은 것 (200자에서 자름)
  "createdAt": 1760000000000,
  "updatedAt": 1760000000000,
  "files": [                            // 있으면 파일 글. 최대 10개.
    { "path": "users/{uid}/{noteId}/0/스크린샷.png", "name": "스크린샷.png", "type": "image/png", "size": 183022 },
    { "path": "users/{uid}/{noteId}/1/보고서.pdf",   "name": "보고서.pdf",   "type": "application/pdf", "size": 52011 }
  ],
  "thumb": "data:image/jpeg;base64,..." // 선택. 첫 번째 이미지의 미리보기
}
```

- `text` 를 파일 이름으로 채워 두는 이유: 이 기능 이전 버전(APK 1.2, 위젯 1.1)은 `files` 를 모르므로
  적어도 파일 이름을 글로 보여 주고 복사합니다. 규칙상 `text` 는 비어 있으면 안 됩니다.
- `files` 가 없으면 지금까지와 같은 글입니다.
- `type` 을 모르면 `application/octet-stream`.
- 이미지(`type` 이 `image/` 로 시작)인지 여부는 `type` 으로만 판단합니다.

## 제한

| 항목 | 값 | 강제하는 곳 |
|---|---|---|
| 파일 하나 | 10 MB (소유자 100 MB) | `storage.rules` + 각 클라이언트가 올리기 전에 확인 |
| 글 하나의 파일 수 | 10개 | 클라이언트 (규칙 언어로는 개수를 셀 수 없음) |
| `thumb` | 60,000자 이하, `data:image/` 로 시작 | `database.rules.json` |

## 미리보기 (`thumb`)

- 첫 번째 이미지 파일만. 긴 변을 **320px** 에 맞춰 줄이고 **JPEG 품질 70%**, base64 data URL.
  (보통 10~25KB.) 60,000자를 넘으면 품질을 낮추거나 생략합니다.
- 위젯·목록이 Storage 를 건드리지 않고 미리보기를 그릴 수 있게 하려는 것입니다.

## 파일 이름 다듬기

모든 클라이언트가 같은 규칙으로 다듬습니다.

1. `\ / : * ? " < > |` 와 제어 문자(U+0000–U+001F) → `_`
2. 앞뒤 공백·마침표 제거
3. 200자를 넘으면 확장자를 살려 앞부분을 자름
4. 비면 `file`
5. 이름 없는 이미지(스크린샷을 그대로 붙여넣은 경우): `이미지-YYYYMMDD-HHMMSS.png` (로컬 시각)

## 순서

**올리기** (새 글 = 바로 위젯에 고정, 텍스트 글과 같은 규칙)

1. `noteId = push(notes).key`
2. 파일마다 Storage `users/{uid}/{noteId}/{i}/{name}` 에 올림 (contentType = `type`)
3. 한 번의 `update(users/{uid})` 로 `notes/{noteId}` 와 `pinned: noteId` 를 함께 씀
4. 3이 실패하면 2에서 올린 파일을 지웁니다.

**지우기** — 글을 지운 뒤, 그 글의 `files[].path` 를 Storage 에서 지웁니다(실패해도 무시).

**수정** — 파일 글은 고쳐 쓰지 않습니다. 각 클라이언트는 파일 글에서 수정 기능을 숨깁니다.

## 받는 쪽에서 "복사" 하면

| 받는 곳 | 이미지 1장 | 그 외(일반 파일, 여러 개) |
|---|---|---|
| 웹앱 (브라우저) | 이미지를 클립보드로 (PNG로 바꿔서) | 브라우저는 파일을 클립보드에 넣을 수 없음 → **내려받기** |
| Windows 위젯 | 파일 목록 **과** 그림을 함께 클립보드로 (탐색기에 붙이면 파일, 카톡·문서에 붙이면 그림) | 파일 목록을 클립보드로 → 탐색기에서 붙여넣기 |
| 안드로이드 | `content://` URI 로 클립보드 (붙여넣기를 지원하는 앱에서 그림으로) | 같은 방식 + 앱에서 **공유** 버튼 |

받은 파일은 각 기기의 로컬 폴더에 받아 두고(같은 경로는 다시 받지 않음) 거기를 가리킵니다.
